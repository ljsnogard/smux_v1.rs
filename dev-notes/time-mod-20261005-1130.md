## 1. 本轮做了什么

新增公开模块 `smux_v1::time`，公开面与 compio 的 `runtime::time` 基本一一对应：

| 项 | 形状 |
| --- | --- |
| `Elapsed` | `thiserror` 派生的错误类型，文案「期限已到」；字段私有 ⇒ 调用方无法伪造 |
| `Interval<C>` | `tick(&mut self) -> C::Instant`，相位对齐（不是「上一觉之后再等 period」） |
| `Timer<C>` | **每个连接一个**的轮盘句柄（`Clone` = `Rc` 计数 +1） |
| `sleep` / `sleep_until` | `(timer: &Timer<C>, …)` |
| `timeout` / `timeout_at` | `(timer, …) -> Result<F::Output, Elapsed>`，手写 `poll_fn` select |
| `interval` / `interval_at` | `(timer, …) -> Interval<C>`；`period == 0` 在构造点断言 |

内部（`pub(crate)`）：`TimerWheel_`（`BTreeMap<(期限, 生成序号), Option<Waker>>`）、
`TimerKey_`、`Sleep_`（私有）。

## 3. 因果链条：为什么是「显式 `Timer` 参数」

compio 的 `sleep_until(deadline)` 敢只收一个 `Instant`，靠的是 `Runtime::with_current`
摸到一个**全局**运行时里的 `TimerRuntime`。本仓没有这个全局对象，且**不可能**有：
连接要同时支持 tokio 与 compio，运行时是调用方注入的（`S: TrLocalScope`）。

因此把「compio 里由运行时隐式持有的轮盘」提成**显式参数** `Timer<C>`：每个连接一个，
由调用方构造、tick 循环与各等待者各持一份 `Clone`。这是与 compio 的**唯一**必要偏离，
其余名字与语义尽量保持同形（含「平局时内层赢」这种细节，以便将来对照阅读）。

## 4. 两处**刻意强于** compio 原版的地方

### 4.1 唤醒在借用之外（修掉一个 `RefCell` 重入面）

compio 的 `TimerRuntime::wake` 在 `borrow_mut()` **之内**逐个 `waker.wake()`。若某个
waker 同步重入 `poll` 并再次借轮盘，就是一次 `RefCell` 重入 panic。本仓既有的纪律正是
「锁内只置位 / 取 waker，锁外 `wake`」（`keepalive…` §6.3 记的同类隐患）。

本模块因此把 `wake` 拆成两步：`take_expired_` 在借用内**切出**一个局部 `BTreeMap` 并
结束借用，随后在借用之外唤醒。切出的节点随返回值移动、唤醒完整体释放，**不额外分配**。

### 4.2 生成序号 + 明确不 panic

`TimerKey_` 的 `generation_` 让**同期限**的多个等待者互不覆盖（没有它，后者会把前者的
waker 槽顶掉 ⇒ 前者永不醒）；真回绕（2^64 次登记且同期限者仍在册）的后果只是「先登记
者的 waker 被顶掉」，故用 `wrapping_add` 而不是 compio 那样的 `expect`（AGENTS §6）。

## 5. 测试策略：为什么**没有**用 `dual_runtime_test_!`

本模块**故意不含运行时相关行为**：轮盘不会自己醒来，唤醒源（tick 源）由调用方注入，
而那个形状尚待裁决（`keepalive…` §5.2）。搬真实运行时反而会把「被测的确定性逻辑」与
「运行时的调度粒度」混在一起，把判定退化成看门狗掐时间。

于是用**假时钟 + 虚拟时间驱动**（`FakeClock_` 跑微秒刻度 `Instant64<1_000_000>`，
`drive_` 每轮把时钟直接推到最近期限再 `wake`），13 个 `#[test]` 钉住：

- 到期判据是 `deadline <= now`：差 1 µs 不醒、正好到点醒**恰好一次**；
- 期限已过者**不占位**；未就绪即丢弃者**撤销登记**（轮盘不留悬空 waker）；
- 同期限两个等待者互不覆盖；
- `timeout`：内层先完成 ⇒ `Ok` 且撤销登记；期限先到 ⇒ `Err(Elapsed)` 且**丢弃内层**；
- `interval` / `interval_at` 的相位对齐；零周期在构造点拒绝。

真实运行时的端到端用例（真实 tick 源 + 真实时钟 + 两个运行时各一遍）**留给 §5.2 裁决
之后**，按本仓做法落到 `tests/` 下按运行时各跑一遍。

## 6. 本轮**未**做、且需要裁决的事项

1. **轮盘的分配器**：`TimerWheel_` 的 `BTreeMap` 目前用**全局**分配器（照抄 compio），
   没有像 `registry_` 那样注入 `A: AllocatorClone` ⇒ 每登记一个等待者是一次全局分配。
   本轮把它当**内部**细节（`TimerWheel_` 不公开），因此现在改不算公开面变更；但
   `tests/alloc_count.rs` 的基线将来要为它补一条上界（`audit…` §G 已登记这一预期）。
2. **`x_deps` 是否导出 `embedded_timers`**：现在**没有**导出，于是 `Timer<C>` 的
   `C: Clock` 约束里出现了一个「用户必须自己也依赖 `embedded-timers`、且版本要一致」
   的公开依赖风险。裁决前它是已知代价。
3. **`keepalive…` §5 的 6 项**仍然全开：超时语义、异步等待源（tick 源）、PULSE 阈值与
   限频、`Clock` 注入形状、唤醒落点、tick 频率。本模块只把「§5.4 的一部分」落地为
   「`Clock` 由调用方给值、模块泛型化」，**没有**规定它从 `new` 还是 `TrConnCfg` 注入。
4. **登记不唤醒驱动方**：新登记更早的期限时，驱动方可能正等在一个更晚的期限上。本模块
   只提供 `min_timeout()` / `len()` / `is_empty()` 供驱动方判断，**不预判**通知落点
   （§5.5 的三选一）。这是接入连接层前必须闭合的一环，否则会出现「等过头」。
