# dock 宏化与无损 `From` 转换（2026-10-17 22:54）

## 背景

`abs_smux/src/dock.rs` 里 `impl TrDock for Dock<u8>` … `Dock<isize>` 是十份逐字
重复的实现；同时希望 `Dock<u32>` 能直接由 `u8` / `u16` 构造（因为标准库已保证
这些转换无损），无需调用方手写 `Dock::new(x.into())`。

## 决策

1. **用一个私有宏 `impl_dock_!` 同时生成两类实现**：调用点形如
   `目标类型 => [源类型, ...]`，每个条目展开出一个 `impl TrDock for Dock<目标>`
   以及若干 `impl From<源> for Dock<目标>`。重复的 `TrDock` 实现从此只由类型名
   列表驱动，新增整型只需加一行。
2. **保留 `impl<T> From<T> for Dock<T>`**（自反转换），矩阵里只列异型转换，
   避免自反组合在矩阵中重复出现。
3. **转换体写作 `Dock(<目标>::from(value))`**，把"是否无损"交给标准库的 `From`
   实现判定；矩阵若写错（某组合在 std 中不存在），生成的代码直接编译失败，
   而不是像 `as` 那样静默截断。
4. **不采用"按源类型泛型化"方案**
   （`impl<T: Integral + From<u8>> From<u8> for Dock<T>`）。它虽然能省掉矩阵，
   但：其一，会与自反的 `impl<T> From<T> for Dock<T>` 在 `T = u8` 处冲突，
   必须删掉自反实现；其二，会把 `From<u8> for Dock<T>` 铺到所有
   `T: From<u8>` 上，下游若想为自己的整型 newtype 提供 `Dock<Local>` 的
   `From<u8>` 就会撞上 coherence。用户选择显式矩阵，转换集合完全可控。

## 矩阵依据（标准库保证的无损 `From`）

| 目标    | 源类型                          |
|---------|---------------------------------|
| `u8`    | —                               |
| `u16`   | `u8`                            |
| `u32`   | `u8`, `u16`                     |
| `u64`   | `u8`, `u16`, `u32`              |
| `usize` | `u8`, `u16`                     |
| `i8`    | —                               |
| `i16`   | `u8`, `i8`                      |
| `i32`   | `u8`, `u16`, `i8`, `i16`        |
| `i64`   | `u8`, `u16`, `u32`, `i8`, `i16`, `i32` |
| `isize` | `u8`, `i8`, `i16`               |

`usize` / `isize` 的位宽随平台变化，所以只收 `u8` / `u16`（以及对应的有符号
窄类型），不收 `u32` / `i32`：标准库也不提供 `u32 -> usize`、`i32 -> isize` 的
`From`。整张矩阵已用独立 `rustc` 小程序逐项验证 `目标::from(源)` 存在。

## 备注

- `Dock::unspecified()` 沿用原有语义：`T::ZERO`，即**所有类型（含有符号）都是
  0**；`wildcard()` 是 `T::MAX`。测试按此断言，未改变既有行为。
- 新增的 `From` 实现属于公开 API 的**增加**；自反 `impl<T> From<T> for
  Dock<T>` 保留，因此 `Dock<T>: From<T>` 的既有能力不变。
