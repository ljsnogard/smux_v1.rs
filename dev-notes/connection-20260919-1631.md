## 0. 结论速览

1. 本轮先做「类型 + 文档」骨架，把设计决策固化在代码里：读 / 写**双 session**、
   `buffex` 环形缓冲、dock 自描述线格式、字节信用窗口、半关闭 + 调用方驱动超时、
   `multi-thread` 特性开关、无前缀直观命名。
2. 过程中发现 **`abs_smux` 的两处上游问题**，其中一处是硬阻塞，已按人类决策修订
   （§2、§3）：带载荷的异步方法返回类型无法捕获载荷缓冲；以及 `abs_smux` 依赖了
   与工作区其余部分**不同的 `abs_buff` git 源**，导致两套同名 trait 无法互通。
3. 新增 `TrMuxConfig` 把「环存储类型 / 分配器 / 流控策略」打包，避免公开类型的
   泛型参数膨胀。

## 1. 本轮采纳的设计决策

| 议题 | 决策 | 落点 |
| --- | --- | --- |
| dock 宽度 | 支持 1 / 2 / 4 字节；沿用握手的「自描述字段字节」策略，一个字节同时表达**宽度**与**是 local 还是 remote dock** | `connection/frame_.rs`、`connection/mod.rs` §4 |
| 驱动 / 会话模型 | **读写双 session**：`ReadSession` 独占 `Rx` 做解复用，`WriteSession` 独占 `Tx` 做复用调度，各自独立加锁；`MuxConnection` 以 `&self` 分发多个 `DockBinding`，业务逻辑各持一个会话 | `connection/session_.rs`、`connection/mod.rs` §2 |
| 缓冲分配 | **调用方注入**分配器与策略；每条子流两个 `buffex` 环 | `TrMuxConfig`、`connection/mod.rs` §5 |
| 帧格式 | 新紧凑二进制帧：`header = (val_type << 4) | field_id`，字段序列 + 载荷；`Kind` / `PayloadLen` 必需；数据帧不带 CRC | `connection/frame_.rs` |
| 流控 | 每子流每方向**字节信用窗口**；初始窗口 = 接收环容量；消费过阈值回发 `WINDOW_UPDATE` | `flow_ctrl/mod.rs` |
| 生命周期 | **半关闭**（每方向独立 `FIN`）；`max_channel_timeout` 由调用方驱动（本 crate 不建定时器） | `connection/mod.rs` §7 |
| 线程模型 | `multi-thread` cargo feature 二选一：缺省 `!Send`（单线程运行时），开启后 `Send + Sync`（原子原语，可跨线程 spawn） | `Cargo.toml`、`connection/mod.rs` §6 |
| 命名 | 无前缀直观名：`MuxConnection` / `DockBinding` / `ChannelListener` / `ChannelHandle` / `ChannelTx` / `ChannelRx` / `Telegraph`；`FlowCtrl` / `SendWindow` / `RecvWindow` / `WindowUpdate` / `FlowCtrlError` | 各处 `pub use` |

## 2. 阻塞项：`abs_smux` 的关联类型无法捕获载荷缓冲（已修订）

### 2.1 症状

`abs_smux` 的 5 个带载荷异步方法把载荷缓冲作为**方法泛型**传入，返回类型却是
**只带生命周期参数的关联类型**：

```rust
type OpenChannelAsync<'f>: TrMayCancel<'f, MayCancelOutput = Result<(Self::Tx, Self::Rx), Self::Err>>
where Self: 'f;

fn open_channel_async<'f, R>(&'f mut self, remote_dock: Self::Dock, message: &mut R)
    -> Self::OpenChannelAsync<'f>
where R: TrBuffRead<Self::Data>;
```

`Self::OpenChannelAsync<'f>` 里没有 `R`，future 在类型上无法持有 `message`。

### 2.2 实测证据（`target/probe/`）

「改用 `impl Trait` 关联类型」这条退路同样被拒：

```
error: type parameter `R` is part of concrete type but not used in parameter list for the `impl Trait` type alias
```

即使函数体完全不用 `r` 也报同一个错，说明这是关联类型与**方法泛型**之间的硬约束，
不是生命周期写法的细节问题。受影响方法：`open_channel_async(message)`、
`accept_async(welcome)`、`reject_async(reason)`、`send_async(packet)`、
`recv_async(buffer)`；无载荷的 `bind_async` / `listen_async` / `income_async` /
`open_telegraph_async` 不受影响。

### 2.3 解决方案（人类决策：方案 A）

让关联类型也泛型于载荷类型，并把形参生命周期显式钉到同一个 `'f`：

```rust
type OpenChannelAsync<'f, R>: TrMayCancel<'f, MayCancelOutput = Result<(Self::Tx, Self::Rx), Self::Err>>
where Self: 'f, R: 'f + TrBuffRead<Self::Data>;

fn open_channel_async<'f, R>(&'f mut self, remote_dock: Self::Dock, message: &'f mut R)
    -> Self::OpenChannelAsync<'f, R>
where R: TrBuffRead<Self::Data>;
```

关键点：**GAT 的 where 子句必须带上 `R: TrBuffRead<Self::Data>`**。否则实现方在
定义 `type OpenChannelAsync<'f, R> = 具体类型` 时，只有 trait 声明的 `R: 'f` 可用，
编译器无法证明具体类型要求的 `R: TrBuffRead<...>`，会退而尝试 `R: Borrow<[u8]>` 之类的
无关路径并报 `E0277`。

修订落在 `abs_smux/src/conn.rs` 的 `TrTelegraph` / `TrChannelHandle` /
`TrDockBinding` 三处 trait（共 5 个关联类型 + 5 个方法签名）。
**这是 `abs_smux` 的公开 API 变更**，按纪律 1 已获人类确认。

## 3. 阻塞项：`abs_smux` 依赖了另一份 `abs_buff`（已修订）

`smux_v1` 的依赖图里同时存在两份 `abs_buff` 0.3.0：

```
abs_buff v0.3.0 (gitee .../abs_buff.git?branch=dev/0.3.0#2a17d238)   ← smux_v1 / buffex / handshake 使用
abs_buff v0.3.0 (github ljsnogard/abs_buff.git?branch=dev/0.3.0#2a17d238)  ← abs_smux 使用
```

两者版本与 rev 相同，但**是不同的 crate**（rustc 视为不同类型），于是
`abs_smux` 的 `TrBuffTryWrite` / `TrBuffTryRead` 是另一套 trait，无法在我们基于
`buffex`（其依赖 gitee 版）的类型上实现——`impl TrChannelTx for ChannelTx<...>` 会
因为「`Producer` 未实现那个 trait」而失败。

修订：把 `abs_smux/Cargo.toml` 的 `abs_buff` 源改为 gitee，与工作区其余部分统一。
`cargo tree` 复核后只剩一份 `abs_buff`。

> 为什么之前没暴露：`smux_v1` 只是 `pub use abs_smux;`，尚未实现它的 trait；
> 一旦开始实现就会撞上。

## 5. 骨架结构

```
smux_v1/src/
├── flow_ctrl/mod.rs          # Credit / TrFlowCtrlPolicy / DefaultPolicy / WindowUpdate
│                             # SendWindow / RecvWindow / FlowCtrl / FlowCtrlError
└── connection/
    ├── mod.rs                # 模块文档（trait 映射、双 session、帧格式、dock、缓冲、线程模型）
    │                         # Dock / BufferedTx / BufferedRx / BufferedChannel 别名 + pub use
    ├── error_.rs             # MuxError<RE, WE>
    ├── frame_.rs             # FieldId / FrameKind / flags / FrameHeader + 编解码入口
    ├── session_.rs           # ReadSession / WriteSession + ChannelRegistry（内部）
    ├── channel_.rs           # TrMuxConfig + MuxConnection / DockBinding / ChannelListener
    │                         # ChannelHandle / ChannelTx / ChannelRx + abs_smux 各 trait 实现
    └── telegraph_.rs         # Telegraph + TrTelegraph 实现
```

### 5.1 `TrMuxConfig`

「环存储类型 `B`、分配器 `A`、流控策略 `P`」在整个连接里是同一组，因此打包：

```rust
pub trait TrMuxConfig {
    type Buff: BorrowMut<[MaybeUninit<u8>]> + Send + Sync;
    type Alloc: TrMalloc + Clone + Send + Sync;
    type Policy: TrFlowCtrlPolicy;
    fn allocator(&self) -> Self::Alloc;
    fn policy(&self) -> &Self::Policy;
    fn channel_capacity(&self) -> usize;
}
```

公开类型因此只有 `MuxConnection<R, W, C>` 三个参数，而不是五个。

### 5.2 帧字段编码

`header = (val_type << 4) | field_id`：

- `field_id`（低 4 位）：`Kind` / `Flags` / `LocalDock` / `RemoteDock` / `PayloadLen`
  / `WindowUpdate` / `ReasonCode`，`0x07..=0x0F` 保留；
- `val_type`（高 3 位）：复用握手的 `NegotiationValType`，1/2/3/4/8 字节大端；
- `LocalDock` 与 `RemoteDock` 是两个不同 `field_id`，所以「宽度」与「哪个 dock」
  由同一个字节表达；
- dock 只接受 1/2/4 字节宽度（`BeU24` / `BeU64` 非法）。

### 5.3 会话派生类型的生命周期占位

`ChannelListener` / `ChannelHandle` / `Telegraph` 用类型别名
`SessionMark_<'s, 'f, R, W, C> = PhantomData<(&'s &'f (), fn() -> (R, W, C))>`。
`&'s &'f ()` 把 `'f: 's` 编码进类型：它们派生自「借用了连接的会话」，因此连接
借用的生命周期必须覆盖类型自身。这样 `Self: 'i` 就能推出宏生成类型所需的
`'f: 'i`，无需在每个 impl 里手写 `'f: 's`。

### 5.4 数据面的错误

子流半边是 `buffex` 端半部的薄包装，`Err` 直接就是 `ConsumerError` /
`ProducerError`（已实现 `TrTaggedError<ReadErrTag/WriteErrTag>`），不再包一层
`MuxError`。控制面统一用 `MuxError<RE, WE>`。
