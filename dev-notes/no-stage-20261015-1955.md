# no-stage：从握手交付物直接建连（去掉连接级帧暂存环与两个泵）

分支 `feat/no_stage`。本文记录「`MuxConnection` 不再需要调用方另交两块 stage 缓冲」
这一改动的出发点、方案取舍、内部构造影响、下游 API 影响与验收数据。

---

## 1. 出发点：stage 环是**第二次**缓冲

旧版的连接内部有**五个**循环与**两条连接级帧暂存环**（stage ring）：

```text
网络 Rx ──读泵──▶ 连接读环 ──解复用──▶ 各子流接收环 ──▶ 应用
应用 ──▶ 各子流发送环 ──复用──▶ 连接写环 ──写泵──▶ 网络 Tx
```

而握手交付物里的 `Tx` / `Rx` **本身就自带缓冲**：它要么是 `buffex::ring` 的环半部
（调用方自己造的全被动环），要么是 `buffex_*_adapt` 的 `BuffRead` / `BuffWrite`
（「设备 + 环」适配器，环在它内部）。两种形态都已经提供
`abs_buff::buffer::TrProducerState` / `TrConsumerState`——即「有多少可读 / 可写、
对端是否已封口」的**非阻塞查询**。

也就是说，旧版的「读泵 + 连接读环」与「复用 + 连接写环 + 写泵」做的是同一件事：
**把已自带缓冲的传输半边，再搬进第二条缓冲**。去掉它直接得到两样东西：

- 少一次全量字节搬运（每个方向各一次）；
- 少两个任务、少两块缓冲（及其块分配）。

## 2. 方案取舍

### 2.1 方案 A：把传输固定为「本 crate 自己的环半部」

把 `C::ConnTx` / `C::ConnRx` 直接钉成 `BufferedTx` / `BufferedRx`，内层两个循环一个字
不用改（它们本来就只与这两个类型打交道）。改动最小、语义零损失。

**没有采用**：它会把传输层收窄成「必须用 `smux_v1::connection::new_buffered_channel`
造的环」。而仓内已有三类使用者拿的是别的形态：

| 使用者 | 传输半边 |
| --- | --- |
| `smux_v1` 自己的测试 | `BufferedTx` / `BufferedRx`（可以用方案 A） |
| `smux_v1_listener` 的测试、`smux_v1_sock_demo` | `buffex_*_adapt::BuffRead` / `BuffWrite`（设备 + 环适配器） |
| `examples/active_passive.rs` | `RingWriter<Shared<Ring<..>>>`（调用方自己用 `buffex` 造的环） |

后两类在方案 A 下**全部编不过**，而且 demo 那类无法「包一层」绕过——适配器本身就是
设备 + 环，包进 `BufferedRx` 只会退回「再搬一次」。

### 2.2 方案 B（本版）：泛型 + `abs_buff` 的状态 trait

`TrConnCfg` 的两条传输半边各加一条约束：

```rust
type ConnTx: TrBuffWrite<u8> + TrProducerState;
type ConnRx: TrBuffRead<u8> + TrConsumerState;
```

于是内层两个循环可以在**不 park** 的前提下问出旧版问环的那三件事：

| 旧版问环 | 本版 |
| --- | --- |
| `BufferedRx::consumer_state()`（可读量 / 生产端是否封口） | `TrConsumerState::consumer_state()` |
| `BufferedRx::read_async` / `try_read` | 同名方法（`TrBuffRead` / `TrBuffTryRead`，本来就有） |
| `BufferedTx::producer_state()` | `TrProducerState::producer_state()` |
| `BufferedTx::close()`（退出时封口，唤醒外侧写泵） | **没有对应物** → 见 §6.1 |

删掉的东西：`session_pump_.rs`（两个泵，298 行）、`ring_::StageRingPair_` 及其两个
半部别名、`session_::ByteLoopShared_`、连接构造里的两块缓冲参数。

## 3. 内部构造的变化

### 3.1 循环：5 → 3

| 旧 | 新 | 说明 |
| --- | --- | --- |
| 0 读泵 | — | 交付物自带缓冲，删除 |
| 1 解复用 | 0 解复用 | 直接读 `C::ConnRx` |
| 2 复用 | 1 复用 | 直接写 `C::ConnTx` |
| 3 写泵 | — | 删除 |
| 4 计时 | 2 计时 | 不变 |

令牌数组 `ChannelRegistry_::loops_` / `MuxCore::loops_` 由 `[CancelToken_; 5]` 缩到 3；
`K_LOOP_IDX_WRITE_PUMP` 与 `cancel_loops_keep_pump_` 删除。**`loop_token_(0)` 仍是
`close_async` 的收尾探针**（现在是解复用循环），语义不变。

### 3.2 EOF / 读错误的判定路径变了

旧版：读泵读到 EOF ⇒ 退出 ⇒ **封口连接读环** ⇒ 解复用从 `consumer_state()` 看到
「封口且排空」⇒ 干净返回。

本版解复用直接读传输，因此判定分两处：

- `rx_state_()`：`consumer_state()` 给 `Some((0, true))` ⇒ `Eof`；给 `Some((n, _))`
  ⇒ 可读；给 `None`（传输没实现这个查询）⇒ `Unknown`，**不能当 EOF**（那会静默地
  「干净退出」），交给下面的 park 由 `read_async` 给结论；
- `park_read_wake_()`：park 就绪时把结果分成三种——拿到段 ⇒ `Bytes`；`Err` 且
  `err_tag() == ReadErrTag::Closing` ⇒ `Eof`；其它 `Err` ⇒ `Fatal`（连接级传输错误）。

### 3.3 收尾：「留下写泵」这条纪律消失

旧版为了「`drop` 之后数据不丢」，在优雅关闭的收敛路径上刻意**不取消写泵**，让它把
连接写环里已经成帧的字节搬上传输（`cancel_loops_keep_pump_`）。

本版复用循环成帧时**直接写进传输半边**，因此「成帧写出」与「交给传输」是同一个动作，
连接内部没有待排空的环：收敛路径与超时路径都走 `cancel_loops_()`，那条软收尾被删除。
传输里已经写出的字节由**调用方那一侧**的排空者负责（适配器的自驱动泵 / 调用方的出向
泵），已不属于本连接的生命周期。

### 3.4 传输字节指标的口径变窄

旧版由两个泵上报 `on_transport_bytes`，口径是**线上原始字节**（含尚未成帧的零头与
被丢弃的帧）。本版没有泵，改由内侧两个循环在「一帧搬运完成」处上报**已成型并搬运的
帧字节**（与 `on_frame` 同口径）。`tests/metrics_e2e.rs` 的两条断言因此仍然成立，
但要记住：**原始线字节的账现在属于传输层（调用方）**。

### 3.5 顺带修掉一个真缺陷：`close_async` 的超时判据

改动后发现 `tests/inmem_mux.rs` 的 `mux_graceful_close_timeout_dual_` 变成**不稳定**：

| 版本 | 10 次重复的失败次数 |
| --- | --- |
| `main` + 依赖对齐（8614824） | 0 / 10 |
| 本分支（未修判据时） | 3 / 10 |

根因不在缓冲，而在 `close_async` 的**返回值判据**：它只看「五个（现三个）循环令牌是否
被触发」，而令牌对三种收尾一视同仁——与对端收敛、计时循环的**整体超时兜底**、连接级
失败。旧版只在「调用方自己的期限先到」时返回 `false`，而两个期限**数值相同**：

- 计时循环从 `enter_waiting_close_()` 那一刻起算（连接毫秒，向下取整）；
- 调用方在那之后才算 `rt.now() + max_channel_timeout`。

于是计时循环的期限**天然更早**，旧版只是靠任务调度的那点余量让调用方先醒——这是
时序竞争，不是设计。任务数从 5 降到 3 之后计时循环更准时，竞争就暴露了。

修法是把判据变成**显式事实**：新增连接状态 `K_STATE_FORCED_CLOSE`（2），计时循环认领
「整体超时」时记下它，`wait_for_finalize_` 改成

```rust
probe.is_cancelled() && fail_kind_().is_none() && !is_forced_close_()
```

修后 12/12 稳定通过（§5）。这条与 no-stage 无关，是在本分支上暴露出来的旧缺陷，可以
单独摘出去合入主线的。

## 6. 已知缺口与风险

### 6.1 写半边没有泛型的「封口」钩子（**最需要决策的一条**）

旧版复用循环退出时用 `StageSealGuard_` 封**自己那条**连接写环，好让外侧写泵
「封口且排空」后退出。本版复用循环持有的是**传输**写半边，退出时只能 drop：

- 对**自驱动适配器**（`buffex_*_adapt::BuffWrite`）足够——它的 `Drop` 会关生产端、
  detach 泵、把尾巴搬完；
- 对**调用方驱动的全被动环**（`buffex::ring` 的 `RingWriter`）不够——唤醒 park 中的
  排空方靠的是固有方法 `close()`，而 `TrBuffWrite` 里**没有**它。

因此在这类传输上，连接侧收尾之后调用方的出向泵不会被唤醒（要靠它自己的取消 / 超时）。
补法有三条，需要上游或 API 决策：

1. 上游 `abs_buff` 给 `TrBuffWrite` 加「封口」方法（最干净，但要动上游）；
2. 本 crate 定义 `trait TrConnTx: TrBuffWrite<u8> + TrProducerState { fn seal(&mut self) {} }`
   并提供缺省空实现——但**无法为 `BufferedTx` 特化**（孤儿规则 / 无特化），要让使用者
   自己为自己的传输实现（外部类型实现不了）；
3. 由配置交出「收尾动作」（`TrConnCfg` 加一个方法），把这件事交回调用方决定。

### 6.2 「传输必须自带缓冲」从**结构保证**降级为**使用者责任**

旧版无论调用方给什么 `Rx` / `Tx`，连接都会把它搬进自己的环，因此 `Rx` 就算是一个
**裸设备**（例如 socket 的读写半边）也不会让内层循环 park 在设备上。

本版要求 `ConnTx` / `ConnRx` 自带缓冲：若把裸设备直接接上，解复用循环会 park 在设备
读上、复用循环会 park 在设备写上，事件通道与另一方向都可能被拖住（这正是旧版
`session_` 模块文档列的三条理由）。类型系统只能检查「实现了两个状态 trait」，
**检查不了「它背后有没有另一个任务在驱动」**——使用者若用 `TrProducerState` 的默认
`None` 实现糊弄过去，连接会在第一次写数据时报传输错误（响亮的失败，不是静默错误）。

### 6.3 `park_read_wake_` 会**取消设备读**

解复用循环的 park 同时等「传输可读」与「读事件通道」，事件先到时，传输的 `read_async`
future 被 drop。对**环**这是无损的（段不消费即释放，字节还在环里）；对**适配器**则
取决于它的 `read_async` 在 drop 时的语义（tokio 侧的 `poll_read` 通常可取消；compio /
io_uring 侧需要上游确认「已提交但未消费的读不丢字节」）。旧版只在**收尾**时才取消一次
设备读，本版在**每次读事件**到来时都可能取消。

建议：在适配器侧补一条「drop `read_async` 不丢字节」的验收，或者给
`TrConnRx` 加一个「有数据就立刻给我段、否则告诉我没有」的纯非阻塞查询，让 park 与读
分开。

### 6.4 数据报对传输环容量的要求

`write_frame_to_stage_`（telegraph）要求「当前放得下整帧」才动手，因此**传输环容量必须
≥ 协商的 `max_packet_size`**，否则数据报会被永久推迟。旧版这条约束落在**连接自己**的
64 KiB stage 环上，调用方不用管；本版落在调用方的传输环上（`K_TRANSPORT_RING_CAPACITY`
就是给它的参考值）。测试里传输环取 64 KiB、`max_packet_size` 缺省 4 KiB，因此没有暴露。

### 6.5 `TrProducerState` 返回 `None` 的语义歧义

`ring_space_()` 把 `None` 当作「对端已消失」（进而判连接不可用），但 trait 的缺省实现
也返回 `None`。也就是说「没实现这个查询」与「读端没了」共用同一个信号。当前所有真实
传输都实现了它，因此没有实际影响；若要更稳，应当像读侧那样引入三态（`Space` /
`Closed` / `Unknown`）。

### 6.6 传输字节指标

见 §3.4：口径从「线上原始字节」变成「帧字节」。要恢复原口径，只能由传输层（调用方）
上报——连接已经看不到「尚未成帧的零头」。
