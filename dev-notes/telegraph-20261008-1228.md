# telegraph 接收路径重构：整帧投递 + 接收侧自拆

> 主题：`connection::telegraph` 的**接收方向**。
> 本文记录本轮（承接 `telegraph-20261007-1630.md`）重新裁决的语义、最终实现形状，

## 1. 本轮定稿的接收语义（用户裁决）

上游 `abs_smux` 把「收一条报文」重新定义成一个**自描述对象**
（`TrRecvDatagram`：`Self: TrBuffSegmRef<'a, C::Data>` + `remote_dock()`）。据此本轮的
接收侧行为改为：

1. **判定是 `DATAGRAM` 帧且本地表里有接收方**（该 `local_dock` 的 telegraph 接收上下文
   已在册）→ 把**整帧**（帧头 + 载荷）直接投给 telegraph 的接收上下文，由它自行拆出
   「远端地址」与「载荷」；
2. **没有任何接收者** → 收到 telegraph 报文就**整个 frame 丢弃**（连丢弃计数都不记：
   对端可能按 `wildcard` 发来，那不是违例，也无人可归因）；
3. 解复用循环（中心循环）**不认识 `DATAGRAM` 的字段语义**——它只做「查表 + 投递」。

### 1.1 为什么是「环绕整帧、接收侧自拆」

- 上游要的是「载荷段 + 远端地址」两样东西同时交付。远端地址只存在于帧头里，而载荷
  紧随帧头；把二者**一起**放进接收环之后，接收侧借出一段就同时拿到了全部信息，
  不需要在队列里再维护一份地址副本；
- 丢弃天然以**整帧**为单位：容量判定用「帧头长度 + 载荷长度」，与「装不下就整条丢弃」
  的既有语义完全一致；
- 中心循环因此彻底不碰数据报字段，`DATAGRAM` 的协议理解只留在 `frame_`（编码 /
  解析规则）与 `telegraph::recver_`（拆分）两处。

## 2. 最终实现形状

| 位置 | 内容 |
| --- | --- |
| `telegraph/recv_ctx_.rs`（新） | `TgRecvCtx_`：解复用循环持有的接收上下文（本端 dock + 身份句柄 + 接收环写端）。`deliver_frame_(header, payload, metrics)` 负责**重新编码帧头** → 容量判定 → 整帧落环 → 入队**帧总长** → 唤醒 |
| `session_.rs` | `TgReadEntry_` 删除，读表值类型换成 `TgRecvCtx_`；`FrameKind::Datagram` 分支缩减为「查表 → `ctx.deliver_frame_`」，查不到就 `continue`（整帧丢弃）；`TgAttach` 落地处改为构造 `TgRecvCtx_` |
| `telegraph/datagram_.rs` | `RecvDatagram<'a, S>`：远端地址 + **已跳过帧头**的载荷段，转发 `TrBuffSegmView` / `TrBuffSegmRef`，并实现 `TrRecvDatagram` |
| `telegraph/recver_.rs` | `Receiver` 实现 `TrDatagramRecver`：`recv_async` 等到队列里的帧总长 → 借出整帧 → **只读**解析帧头 → 搬走帧头 → 返回 `RecvDatagram` |
| `telegraph/sender_.rs` | 补 `TrBuffTryWrite<u8>` / `TrBuffWrite<u8>`（转发到发送环），导入迁到 `abs_smux::telegraph` |
| `owner_.rs` | 文档同步：接收方向队列记的是**帧总长**，环里存**整帧原始字节** |

`TgReadTable_` 的键仍只有 `local_dock`——「表里有条目」就是「有接收方」的判据。

## 3. 三个会静默出错的坑

### 3.1 帧头字节从哪来：重新编码，而不是回放

解复用循环用 `frame_parser_` 的 sans-IO 状态机**逐字节消费**连接读环，帧头字节到手时
已经被消费掉、解析器内部也不保留副本（`FrameHeaderParser::buffer_` 只有当前字段）。

因此「把整帧写进接收环」的第一步是拿到帧头字节。两条路：

- **回放**：给解析器加一个「原始帧头缓冲」（`[u8; K_MAX_FRAME_HEADER]` + 长度），
  逐字节记录；
- **重编码**：用 `frame_::encode_header_` 把已解析的 `FrameHeader` 重新成字节。

本轮选**重编码**：它不触碰通用解析器（不影响 channel 的所有帧路径），而且编码与解析
本来就必须对称（`frame_` 内已有两侧对照的用例）。代价是环里的帧头是**本端编码的
规范形式**——对端若用了更宽的字段宽度，两边字节不同，但**拆出来的远端地址与载荷边界
一致**，因此对接收侧自拆没有影响；容量判定与队列记的也是本端编码后的长度，自洽。

### 3.2 `take_segm_ref` 是「可视」不是「消费」

这是本轮最隐蔽的坑，且第一次实现**直接踩中**：测试读到的是**整帧**（帧头也在载荷里）。

`ReclSliceRef::take_segm_ref` 返回一个 `SegmRef`，它只是「从当前偏移取出一段**视图**」；
真正的消费发生在把内容**搬走**之时（`move_items_to_buff` / `move_items_to_segm`），
`SegmRef::drop` 提交的是**它自己的**已搬出量（未搬 = 0）。因此：

```rust
// 错误：取出帧头段后直接 drop —— 父段偏移纹丝不动
if let Some(head) = whole.take_segm_ref(&Demand::exactly(head_len)) {
    drop(head);
}
```

```rust
// 正确：把帧头字节真正搬进一个定长临时缓冲并丢弃，父段偏移才前进 head_len
if head_len > 0 {
    let mut junk = [MaybeUninit::<u8>::uninit(); K_MAX_FRAME_HEADER];
    if let Some(mut head) = whole.take_segm_ref(&Demand::exactly(head_len)) {
        let moved = TrBuffSegmRef::move_items_to_buff(&mut head, &mut junk[..head_len]);
        debug_assert_eq!(moved, head_len);
    }
}
```

**教训**：`buffex` 的段是「消费记账」模型，任何「跳过一段前缀」的操作都必须**真的把
前缀搬走**；`take_segm_ref` 的返回值不是「已消费」，只是「可消费窗口」。

### 3.3 `remote_dock` 是镜像语义：接收侧要取 `LocalDock`

帧头是**镜像**语义（与 channel 的 `pair` 同源）：发送方把自己的 dock 写在 `LocalDock`、
把**目的地址**写在 `RemoteDock`；接收侧按 `RemoteDock` 找自己的端点。因此：

- 对**接收方**而言，「这条报文来自哪个远端垛口」= 帧头的 `LocalDock`；
- 帧头的 `RemoteDock` 只是**本端自己的地址**。

第一版实现照抄了「`header.remote_dock()`」当作远端，结果集成测试断言拿到的是
`Dock(11)`（本端地址）而不是 `Dock(7)`（对端地址）。这与旧日志 §3.1 记的教训同源：
**同一个字段名在收发两侧语义可能相反，必须两侧对照**。

### 3.4 附带：`Demand` 必须与环半部同寿

`RingReader::try_read<'f>(&'f mut self, demand: &'f Demand<usize>)` 要求环半部与
`Demand` **同寿**，而返回的段要活到 `&'f mut Receiver` 的整个借用周期。因此借段用的
`Demand` 不能是 `recv_async` 的局部量——它是 `Receiver::recv_demand_` 字段，借出时与
`ring_rx_` **分别借用**（不同字段互不冲突）。

## 4. 验证

| 层次 | 结果 |
| --- | --- |
| 编译 | `cargo check --lib` / `--all-targets` 均零警告通过（迁移前该分支有 **17 个错误**） |
| 单元测试 | `cargo test --lib` → **220 passed** |
| 进程内直连 | `cargo test --test inmem_mux` → **16 passed**（含 `mux_telegraph_inmem_dual_`） |
| 真实 UDS · compio | `cargo test`（默认）→ 全绿，含 `telegraph_socket_compio_` |
| 真实 UDS · tokio | `--no-default-features --features test-tokio-runtime --test smoke_tokio` → **5 passed** |
| 真实 UDS · smol | `--no-default-features --features test-smol-runtime --test smoke_smol` → **5 passed** |
| metrics | `--features metrics --test metrics_e2e` → **1 passed** |

telegraph 场景新增的验收点：收到的 `RecvDatagram` 必须同时给出**远端地址**
（= 对端的 `local_dock`）与**载荷**；空报文仍然是一条真报文（长度为 0）；接收环装不下
的 200 字节那条仍然**整条丢弃**，紧随其后的空报文必须是下一条。

## 5. 本轮顺带修掉的回归与遗留

1. **`lib.rs` 的 `x_deps` 回归**：HEAD 提交 `Split telegraph logic` 误删了
   `pub use abs_art::RuntimeTag;` 与 `pub use buffex::x_deps::abs_buff;`，测试侧因此
   编译不过。本轮恢复这两项导出（不是新增 API，是恢复）。
2. **`DockBinding` 的字段访问**：telegraph 开启路径需要连接指针与 `local_dock`，
   本轮加了 `conn_()` / `local_dock_()` 两个 `pub(crate)` 访问器，而不是把字段放宽。
   `map_reserve_err_` 也从 `binding_` 逐项 `pub(crate) use` 出来复用（避免第二份
   「预留失败 → `BindingError`」的理解）。
3. **`use` 规范**：`format_use_imports.py --check` 当前只剩 2 处**既有**违规
   （`tests/inmem_mux.rs:34` / `:61`），本轮新引入的导入全部合规。既有两处未动：
   按纪律 `--fix` 前要先建立可回退点，且与本次改动无关。
4. **rustdoc**：本轮新引入的 broken intra-doc link 已全部清零（`TrTelegraphTx` →
   `TrDatagramSender`、`abs_smux::conn::TrTelegraph` → `abs_smux::telegraph::TrTelegraph`
   等）；仓库里其余模块仍有**既有**的 rustdoc 警告（`config_` / `channel_handle` /
   `owner_` 等），不在本次范围。
5. **依赖形态未变**：`Cargo.toml` 仍走 `abs_smux = { path = "../abs_smux" }`
   （上游改动尚未推到 gitee），与旧日志 §5.2 的遗留项一致。
